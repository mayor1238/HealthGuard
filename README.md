# HealthGuard

A health insurance platform designed around the problems of the Nigerian health insurance ecosystem. It connects **members, hospitals, HMOs and the regulator** in one system.

> **Status:** working prototype. The frontend runs on in-browser demo data; the **backend API** (`server/`, PostgreSQL) is built and tested but not yet connected to the frontend. Organisation names are fictional. Payment, NIN, SMS and bank-payout integrations are stand-ins (see the roadmap).

## The problems it targets

| Problem | What HealthGuard does |
|---|---|
| Most Nigerians are uninsured, and schemes assume a monthly salary | Members can pay **daily, weekly, monthly, quarterly or yearly** by USSD, mobile money, card, transfer or an agent. **Group codes** for markets, cooperatives and employers. **Sponsored cover** for vulnerable people (BHCPF, state equity funds, donors). |
| Hospitals wait months to be paid by HMOs | **Rules-based auto-adjudication** decides every claim line instantly, with a reason for each decision. Hospitals see a **live preview** of what will be paid before they submit. Each HMO has a **payment target**, overdue claims are flagged, and payment speed is published. |
| Fraud: duplicate bills, padding, ghost enrollees | **NIN verification** at enrolment, **check-digit IDs** (typos are caught at the front desk), and a **fraud engine** that scores each claim and holds risky ones for human review. **Members confirm or dispute** every visit billed in their name. |
| Slow eligibility checks and PA (pre-authorisation) codes | Search by ID, phone or NIN for **instant eligibility and benefits**. Routine **PA codes are issued in seconds**. Surgery and high-cost requests go to an HMO doctor with a **24-hour deadline**. |
| Insured patients still pay out of pocket | **Plain-language benefits** with co-pays shown upfront, a **"Know your rights"** page, and a **complaint line** (app or USSD) that escalates to the regulator after 48 hours. |
| Capitation paid late or underpaid | Monthly capitation per member is calculated automatically and tracked as paid, due or overdue. |
| Little choice or competition between HMOs | At enrolment, members see each HMO's **payment speed and complaint-resolution record**. Members can **switch primary hospital** at any time. |
| Regulators lack data | A **live regulator dashboard** shows coverage by state and sector, coverage gaps, an **HMO league table** (days to pay, loss ratio, complaints), fraud caught and escalated complaints. |
| Low smartphone and data access | A full **USSD menu** (`*347*44#` in the simulator) lets members check cover, pay, find a hospital, report a problem and get their ID. |

## Portals

- **Join** (`#/enroll`): 4-step enrolment covering identity and NIN, plan and price, HMO and hospital, then payment.
- **Member** (`#/member`): digital ID card with QR code, cover status, benefit used, payments, visits and bills (confirm or dispute), complaints.
- **Hospital** (`#/provider`): verify a patient, request a PA code, submit a claim with a live decision preview, track claims, see capitation.
- **HMO** (`#/hmo`): overview KPIs, fraud review queue, batch payment to providers, PA approvals, complaints, capitation run.
- **Regulator** (`#/regulator`): scheme-wide KPIs, HMO league table, members by state and sector, fraud flags, escalated complaints.
- **USSD** (`#/ussd`): feature-phone simulator. Payments and complaints made here show up in every other portal.

Use the "Viewing as / Signed in as" selector on each portal to switch between demo personas: a Lagos trader, a Kano okada rider, a salaried employee in Ibadan, and a sponsored pregnant woman.

## Code layout

```
src/
  domain/            Pure business logic with no React. This is where the rules live.
    types.ts         Data model (Enrollee, Claim, PARequest, Complaint, ...)
    catalog.ts       Plans & benefits, HMOs, providers, tariff list, group codes
    pricing.ts       Premium quotes, cover extension, eligibility (active/grace/waiting/lapsed)
    adjudication.ts  Claims engine: coverage, referral/PA, tariff caps, per-visit caps, annual limit
    fraud.ts         Fraud rules and risk score
    preauth.ts       Instant vs. manual PA decisions
    ussd.ts          Stateless USSD menu (same shape as real USSD gateways)
    analytics.ts     HMO scorecards and scheme-wide KPIs
    seed.ts          Deterministic demo data, generated by running the real engine
    domain.test.ts   Unit tests for the rules
  state/store.tsx    In-browser store (localStorage). Every action calls the domain layer.
server/              Fastify + PostgreSQL API that runs the same src/domain code (see server/README.md)
  pages/             One file per portal
  ui/kit.tsx         Shared UI components and routing
```

The domain layer has no UI dependencies, and the API in `server/` imports it unchanged. The next step is to replace the action bodies in `store.tsx` with calls to the API.

## Key rules (configurable in code)

- Grace period: 7 days after cover runs out. Waiting period: 14–30 days depending on plan. Emergencies are always covered.
- Dependants add 60% of the principal's premium each (maximum 5). Quarterly payment saves 3% and yearly saves 8%.
- Primary care must be at the member's registered clinic. Care elsewhere, or at a secondary or tertiary hospital, needs a referral PA code (except emergencies).
- A PA code covers an episode of care. For example, a surgery PA also covers the admission, drugs and tests that go with it.
- Claims with a risk score of 40 or more go to human review. Everything else is decided automatically.
- PA requests up to ₦150,000 (except surgery) are approved instantly. All PA codes are valid for 14 days.

## Roadmap to production

1. ~~Backend API and database with role-based auth and audit logs~~ — done (`server/`). Next: connect the frontend to it.
2. Integrations: NIMC (NIN verification), payment gateways and mobile money, a USSD/SMS aggregator, and a bank payout API for claims and capitation.
3. Standards: ICD-10 diagnosis coding, the official NHIA tariff and benefit package, HL7 FHIR for claims exchange, NDPA 2023 data-protection compliance.
4. Smarter fraud detection (provider peer comparison, anomaly models), with a human always reviewing before a rejection.
5. Offline-first mode for clinics with poor connectivity, and support for local languages (Hausa, Yoruba, Igbo, Pidgin).
